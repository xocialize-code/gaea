**Gaea is alpha.** MES and Gaea are still changing as more plugins arrive, so read each release's notes before you
update.

**Not released yet.** 1.7.0 waits for the media-engine-spec release that adds `mesh.generate_part` (asked in
AB-A-0280). Until Gaea is built on that release it lists no such operation, whatever a plugin offers.

What's new in 1.7.0: a part made to fit a body (`mesh.generate_part`), for plugins whose model makes one part of a
character for the body it goes on. The first is HairDeck: a picture, the head's box and the body's VRM give a hair item.

- **The request:** an `image`, the `body` (a GLB or `.vrm`, as a file or an asset) and `subject_box`, where in the
  picture the part is, as `{x, y, width, height}` in shares of the upright image. `part`, `physics` (chain bones and
  `VRMC_springBone`) and `texture` (`atlas` or `none`) are optional.
- **The result is never moved.** It comes back in the body's coordinates. Gaea writes the disclosure and licences into
  `asset` and renders the preview. It adds no root node and doesn't scale, ground or decimate the part, so its skin,
  inverse bind matrices and spring bones reach the client as the model wrote them.
- **The picture reaches the model upright**, so the box means the same to every model. A picture with transparency is
  used as it is cut out; an opaque one needs an offer that removes backgrounds.
- **Plugins on mlx-engine-swift 0.78.0 install:** a manifest with a `characterPart` model (engine contract 1.63.0)
  decodes. Earlier Gaea versions can't read one.

For plugin authors: GPP-1 §3.3.4 says what a worker receives, and GaeaPluginKit 0.13.0's `CharacterParts` maps it to
the engine's request. The demo plugin 0.5.0 has a stand-in, `demo-part`.
