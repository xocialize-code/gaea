**Gaea is alpha.** MES and Gaea are still changing as more plugins arrive, so read each release's notes before you
update.

What's fixed in 1.7.1 (AB-A-0267, found by PixelAgencyEditor): `image.fill`, `image.extend` and `image.erase` are now
offered only with models this server can finish them with.

- **What went wrong.** A server with only Z-Image listed it on `image.fill` and `image.extend`, and every such job
  failed with "No plugin model offers image.fill". Z-Image's edit re-generates the whole picture at a strength; it can't
  paint a region it is shown. So its result was rejected twice, and the fallback inpainter (LaMa, in gaea-plugin-forge)
  wasn't installed.
- **Models that can't paint a region aren't offered on these operations.** A plugin says so on its `image.edit` offer
  (`supports.image_to_image`, GPP-1 §4.3). Z-Image 0.2.1 does. A request that names such a model is refused when it
  arrives, not after two wasted runs.
- **`image.extend` needs the inpainter, so it's offered only with one enabled.** Extend always uses it: to fill the new
  area itself, or to bridge the seam after an edit model painted it.
- **`image.fill` with an instruction editor (Klein, Qwen) is still offered without an inpainter.** It needs one only
  when the editor leaves the area unpainted twice. If that happens with none enabled, the error now says the inpainting
  model is missing and that LaMa comes with gaea-plugin-forge.
- **Update Z-Image to 0.2.1** (`gaea plugins update com.xocialize.gaea.z-image`). Until then a server with an older
  Z-Image and no inpainter still lists it on `image.fill`.
