# Gaea: area contract

## Bridge identity

**AREA-ID: `gaea`** (aliases: `gaea-mes-media-server`, `gaea-server`, `quanos`). Work in this directory answers for
that identity on the bridge.
- **Session start:** `bridge assume gaea` gives owed asks, open tasks and the context pack in one command.
- **Assumption** is informational, never a lock. A stale last-assumed age in `bridge areas` means nobody is home, and
  you take over by assuming.
- **Filing:** file answers and asks under this id; the roster validates recipients.

## What Gaea is

Gaea is the production MES media server: **one engine for the Image, Audio and Video profiles**, whose models are
**plugins**. A plugin is a signed `.gaeaplugin` executable bundle that Gaea installs from a Git repo URL and runs in a
process of its own.
- **Gaea (the host)** does the MES front end, the queue, memory across processes, the plugin lifecycle,
  `gaea.sqlite` and the UI.
- **The plugins** do the generating.
- **It replaces** the separate Pixel Agency Image and Video Engines (`ml(x)/PixelAgency/Docs/Engines-PRD.md`).
- **"Quanos"** was the working name before Gaea.

## Standing rules

- **Clients speak MES only** (G-3, G-17). Gaea has no client-facing admin API. A server is configured in its own UI.
  The operator API is local to the server's Mac.
- **Signing.** Gaea and its plugins use Developer ID Application: Dustin Nielson (CFZS6RXUCP), with hardened runtime,
  and are notarized in CI. No sandbox and no App Store (G-6). CI's four signing and notary secrets are organization
  secrets on xocialize-code ([Docs/Signing secrets.md](Docs/Signing%20secrets.md), `tools/set-signing-secrets.sh`).
- **The repos live in the xocialize-code organization** (moved from `xocialize` on 2026-10-29; GitHub redirects the old
  URLs). Create new plugin repos there.
- **Trust comes from the signature, never the URL** (G-7, G-18). Verify the bundle with a Developer ID requirement
  built from the trusted teams (the trust list), and launch with `Process.launchRequirement` pinned to the plugin's
  team. Gaea itself, its updates and the operator CLI stay pinned to our team alone.
- **Adapters (LoRAs) are not plugins** (GPP-1 §4.8). Plugins ship catalogs in their manifests; the operator adds one by
  Hugging Face URL (`gaea adapters add <url> --model <id>`), registered plain, pinned to a commit and sha256.
- **Plugins ship no UI code.** Their settings forms come from manifest descriptors, rendered by MESFormsUI.
- **Other areas' repos change through asks:** `bridge ask --to mlx-engine | mlx-apps | …`. That covers
  mlx-engine-swift, media-engine-spec, mlx-image-runtime and the Pixel Agency apps (plan §4). Don't edit their docs
  silently.
- **Building and checking the host.** `swift build`, `swift test`, then `scripts/build-app.sh` for a signed Release
  `dist/Gaea.app`. This volume is case-insensitive, so the app's target is `GaeaApp`, the CLI's is `GaeaCLI`, and the
  binaries are `Gaea` and `gaea` in different folders. `GAEA_HOME` moves Gaea's folder (keep it short: the operator
  socket's path is at most 103 bytes). The models root (MLXEngine's store by default) is `gaea models root <folder>`,
  Settings in the app, or `--models-root` for one launch. A model's default lane is `gaea models lane <id> <lane>`;
  `--budget-bytes` shrinks the memory budget to stage eviction and fallback. `GAEA_GITHUB_TOKEN=$(gh auth token)` reads private plugin repos; Gaea never
  stores it.
- **MLX in a plugin finds its metallib through the plugin's own main bundle**
  (`Contents/Resources/mlx-swift_Cmlx.bundle`). When testing, hide the build folder: MLX falls back to build paths.
  `build-plugin.sh` builds the worker alone in `.build/plugin` and copies every SwiftPM resource bundle it links:
  `Bundle.module` traps on a missing one (AB-L-0318).
